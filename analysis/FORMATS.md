# Centurion: Defender of Rome (1990) — форматы файлов

Разобрано в ходе декомпиляции. Инструменты: `../analysis/`.

## Архивы .DIR/.DAT

Каждый модуль — пара `XXX.DAT` (данные) + `XXX.DIR` (индекс).

`.DIR` = массив записей по 20 байт:

```
+0  u32  смещение данных в .DAT (начиная с 4; первые 4 байта .DAT не используются)
+4  u16  размер записи
+6  char имя[12]  (напр. "CN2.LZW", "MAP.CBM", "INITDAT.LZW")
+18 u16  флаги: 0x8000 = LZW-сжатие, 0xC000 = CBM (14-байт заголовок + LZW), 0x0000 = сырое
```

## LZSS (файлы .LZW и тело .CBM)

```
+0  u32  размер распакованных данных
+4  поток: флаг-байты, биты читаются LSB-first:
      бит 1 = литерал (1 байт копируется)
      бит 0 = ссылка (2 байта):
              byte0 = младшие 8 бит позиции
              byte1 = [старший ниббл -> биты 8-11 позиции][младший ниббл = длина-3]
Кольцевой буфер 4096 байт, предзаполнен пробелами (0x20),
позиция записи стартует с 4078 (0xFEE). Ссылки — АБСОЛЮТНЫЕ позиции в кольце.
```

Референс — код игры: распакованное ядро, функция по смещению 0x1DF
(`analysis/CENTURIO.unpacked.bin`). Декодер: `analysis/gamedec.py`.

## .CBM (полноэкранные/крупные картинки)

```
+0   u16  ширина в пикселях (320, 315, 96...)
+2   u16  x    +4 u16 y      (куда ставить на экране; 0,0 для полноэкранных)
+6   u8   ширина в байтах (= ширина_пикс / 2, с округлением вверх)
+7   u8   высота
+8,9 u8   флаги видеорежима (E* и M* версии различаются)
+10  u32  размер распакованных данных (= ширина_байт * высота)
+14  LZSS-поток (формат выше)
```

Пиксели: **4bpp, 2 пикселя в байте, старший ниббл = левый**, row-major.
Декодер: `analysis/cbm_decode.py` → `decoded/cbm/*.png` (161 файл, все ок).

## Спрайты (пары XXXDAT.LZW + XXXHDR.LZW)

После LZW-распаковки:

- `HDR` = массив записей по 14 байт: `[id:u16][x:u16][y:u16][w:u8][h:u8][u8][u9][ofs:u32]`
- `DAT` = сырые 8bpp пиксели, row-major, спрайты подряд; размер данных спрайта
  = смещение следующего спрайта минус текущее (у последнего — конец файла;
  w*h может на 1-2 байта превышать фактический хвост).
- Поля u8/u9 (байты 8-9 записи) не расшифрованы (у BATL = 0x0D 0x1B, у ENEGO = 0x02 0x1B).

Декодер: `analysis/sprite_decode.py` → `decoded/sprites/<МОДУЛЬ>_<ИМЯ>/`
(66 наборов: гладиаторы, юниты, колесницы, UI-рамки...).

## Шрифт

`OVL0.OVL`, смещение **0x1505C**, 2048 байт = 256 глифов × 8 байт.
1bpp 8x8, байт = строка глифа, бит 7 = левый пиксель (MSB-first), порядок ASCII
(0x00-0x1F пустые, 0x20 пробел, далее стандартно, включая псевдографику).
Файлы: `decoded/FONT_8x8.bin`, `decoded/FONT_8x8.png`.
Крупные заголовки (логотип CENTURION и т.п.) — предрендеренные .CBM, не шрифт.

## Палитры

Готовых RGB-таблиц 256×3 в данных нет — палитры строятся рантайм:

- `CMAP.BIN` (CENT.DAT): первые 48 байт = EGA-палитра 16 цветов (значения 0/21/42/63).
  Остальные 702 байта — remap/градиентные таблицы (не RGB).
- `OVL0.OVL` 0x11F0F — таблица градиентных рамп (16-бит слова), 0xF4B4/0x114C0 —
  remap-таблицы индексов цветов.
- Ядро ставит палитру через `int 10h AH=10h AL=02/AL=12h` (указатель на таблицу —
  аргумент; kernel svc: 0x9740/0x979E в `CENTURIO.unpacked.bin`).
- Эффективная палитра экрана карты (снята с работающей игры): `decoded/MAP_palette.*`.

## CENTURIO.EXE

Запакован **LZEXE 0.90**. Распаковщик: `analysis/emu.py` (эмулятор 8086 стаба).
Результат: `analysis/CENTURIO.unpacked.bin` (~45 КБ) = PLINK86 overlay loader +
ядро сервисов (таймер, клава, мышь, видео, файлы, LZW-декомпрессор @0x1DF).
Основной игровой код — `OVL0.OVL` (96 КБ, не запакован).

## Структура модулей

- `CENT.DAT` — общее: палитра (CMAP.BIN), звуковые драйверы (ADLIB/ROLAND/TANDY/SPEAKER),
  меню (EMENU/MMENU), PLACES (города), NEWGAME, скрипты CN1
- `EINIT/MINIT` — интро (E=EGA, M=MCGA/VGA версии)
- `EMAP/MMAP` — карта
- `ENEGO/MNEGO` — переговоры (TEXTA-Z — тексты, LEADERA-Z — портреты)
- `EGLAD/MGLAD` — гладиаторы, `ERACE/MRACE` — гонки, `ENAVAL/MNAVAL` + `NAVL` — флот,
  `BATL` — сухопутные битвы
