## Как устроено (проверенные факты)
- Текстовый движок ядра: draw_string 0x89C8, measure 0x8C84, draw_char 0x8D82 (в unpacked-образе CENTURIO.unpacked.bin).
- Фильтр байт ≥0x80: знаковый `jl` при `cmp al,0x20` → патч jl→jb @0x8CA4 (measure) и @0x8A8D (draw).
- cbw в measure/draw оставлен НЕТРОНУТЫМ (патч ломал позиции). Вместо него ширины кириллицы лежат в 2 местах: W-0xA0 (для знакового cbw-чтения) и W+0x60 (для беззнакового в draw_char).
- Шрифты: font#1 h=8 (дескриптор-источник ds 0xA05C = file 0x1545C), font#2 h=6 (ds 0xA3B4 = file 0x157B4). Дескриптор = 5 слов [W][Y][B][h|сп][сп|shift], копируется в CRT-блок 0x9B56+ (`rep movsw` из OVL0-кода, сайты si=0xA05C / si=0xA3B4).
- Таблицы font#1 в файле: W 0x1509C(96), Y 0x150FC(96), битмапы 0x1515C(768). font#2: W 0x154B4, Y 0x15514, битмапы 0x15574(576).
- Кириллица (64 глифа, кодировка игры: А-Я=0x80-9F, а-п=0xA0-AF, р-я=0xB0-BF; Ё→Е):
  - ширины f1: file 0x150FC (бывш. Y1) + file 0x14FFC (W-0xA0)
  - ширины f2: file 0x15514 (бывш. Y2) — W2=0xA0B4, W2+0x60=ds 0xA114
  - блок на верхушке DGROUP ds 0xF600..0xFFFF (file 0x1AA00): Y1'(0xA0), B1'(0x500), Y2'(0xA0), B2'(0x3C0)
  - дескрипторы: f1 [9C9C][F600][F6A0], f2 [A0B4][FBA0][FC40]
- DGROUP расширен до 64К: overlay-таблица (образ ядра): размер @0xB084 0xC41→0x1000 параграфов, конец DGROUP @0xB07C 0x2B27→0x2E66, стек лоадера @0xB024 0x2B27→0x2E66. EXE hdr ss link=0x1E66.
- Heap начинается с конца BSS (0xC410) и растёт вверх — блок шрифта нельзя класть туда (первая же редакция так и сдохла).
- CENTURIO.EXE пересобирается БЕЗ LZEXE: link-образ + relocs.json (56 шт, извлечены эмуляцией стаба, emu_reloc.py).

## 2025-11-15: фикс пропадающих букв на экране города
- Причина: для font#2 знаковое (cbw) чтение ширин уходило в W-0xA0 = ds 0xA014 (file 0x15414) —
  там НЕ зеркало, а живая данные (запись туда = чёрный экран на старте). Читался мусор →
  мусорные ширины (В=146, б=64, з/и=0...) → центровка/клиппинг резал буквы выборочно.
- Фикс: W-таблица font#2 переехала целиком в мёртвую зону старых битмапов f1:
  таблица file 0x151FC (ds 0x9DFC) = латинь 0x60 + кириллица 0x40; зеркало file 0x1515C (ds 0x9D5C).
  Дескриптор f2: W 0xA0B4 -> 0x9DFC. Мёртвость ds 0x9D5C..0x9EDC проверена нулями вживую.
- ВНИМАНИЕ: file 0x15414 (ds 0xA014) — ЖИВАЯ область (читается на старте; нули -> чёрный экран).

## 2025-11-16 (4): DS-POCKET схема — рабочая раскладка, борьба с лоадером
- Почему: хвост DGROUP 0xC410..0xFFFF = рабочие буферы (CBM-декод от 0xC948, heap сверху).
  Карман 0xC410..0xC948 (0x538) пуст во ВСЕХ сейвах/экранах — туда кириллица.
- build_ru.py переписан: W1/W2/B1/B2 + пещера (C1..C4, far-call из ядра, Y=1 константой),
  скрэтч глифа в конце кармана. OVL0 дописывается карманом (file 0x17810+).
- PLINK86-лоадер: читает DGROUP из OVL0: seek 0xB400, read (end-start); start считается
  из таблицы/стаба. Если read > размера файла => "Disk I/O error", чёрный экран.
  Оригинал: read=0xC410 (ровно контент). Побочные сборки: 0xCC10 -> ошибка.
  ОТЛАДКА ИДЁТ: какая ячейка/вычисление даёт start (0x1EE6 ориг vs 0x1E66 у меня).

## Механика PLINK86-лоадера (выяснено по трейсу эмулятора)
- DGROUP грузится из OVL0: seek 0xB400, read = min(end-start, [B084]) * 16 байт в ds 0x1E66:0.
- Запись в таблице (образ): start=0xB07A (0x1E66), end=0xB07C (0x2B27), [B084]=лимит (0xC41).
- Если read > контента файла => "Disk I/O error" + цикл => чёрный экран. Поэтому OVL0
  при B084=0x1000 ОБЯЗАН быть 0x1B400 (паддинг), либо B084 оставлять 0xC41 (тогда read=0xC410).
- Сейвы DOSBox-X (save/*.sav): ZIP, чанк Memory = вся RAM — анализ порчи шрифтов делался по нему.
