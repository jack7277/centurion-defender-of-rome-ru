# План: снятие лимитов длины строк (OVL0.OVL)

Сейчас строки OVL0 патчатся **на месте**: новая строка не может быть длиннее
оригинала, потому что следующая строка лежит сразу за ней, а код ссылается
на строки по абсолютным смещениям.

Что уже известно (проверено):
- Строки адресуются 16-битными указателями прямо в коде/данных OVL0.
  Пример: строка `Really Quit?` @0xB572 — её LE16-смещение встречается
  ровно 1 раз, в коде @0x37B.
- OVL0 = 96 КБ (>64 КБ), поэтому строки выше 0xFFFF (интро @0x11852 и далее)
  адресуются иначе: прямых ссылок на 0x1852 (offset-0x10000) нет.
  Механизм надо установить (шаг 1).
- TEXTA-Z / SCOUT — уже без лимита (таблица смещений пересобирается).
- PLACES — фикс. записи по 20 байт, имя <= 17 символов.
- Сборка и откат работают: `build_texts.bat`, `restore_texts.bat`,
  оригиналы в `analysis/orig/`.

## Шаг 1. Карта ссылок на строки
- Для каждой строки из texts.txt (ключ = смещение) найти все вхождения
  LE16-смещения в OVL0. Записать в `analysis/strrefs.json`:
  `{offset: [позиции ссылок]}`.
- Отсеять ложные совпадения: ссылка валидна, если стоит в коде
  (по `analysis/ovl0_disasm.txt`) или в известных таблицах указателей.
- Отдельно разобрать область >0xFFFF: найти код вывода интро
  (строка @0x11852), определить, как вычисляется адрес строки
  (far-указатель seg:ofs или база+индекс).

## Шаг 2. Проверить, можно ли удлинить OVL0
- Таблица оверлеев в ядре `CENTURIO.unpacked.bin` @0xB020: выяснить,
  хранится ли размер/выделяемая память. Если размер жёсткий —
  строки переносим не в конец файла, а в заранее найденные свободные
  области, либо удлиняем файл с правкой таблицы.

## Шаг 3. Сборщик с переносом строк (режим `build --relocate`)
- В `analysis/textool.py` добавить режим: строки, не влезающие в свой
  max, переносятся в новый блок (конец OVL0 или свободная область),
  все ссылки из `strrefs.json` переписываются на новые смещения.
- В texts.txt у таких строк max меняется на `*` (сборка сама это делает
  при следующем dump: max = фактический размер после переноса).
- Порядок: сначала только строки <0xFFFF (механизм известен),
  область интро — после шага 1.

## Шаг 4. Проверка
- `build` → все архивы декодируются, OVL0 ссылается корректно.
- Прогон игры в DOSBox заэкранно (без окон), скриншоты экранов:
  главное меню (Really Quit?), интро, переговоры, события.
- Любая ошибка → `restore_texts.bat`.

## Что это даст
- Полные формулировки вместо усечённых: «Новая игра», «Император»,
  «Сципион Африканский», «Конец хода», нормальные окончания вместо
  «поб.»/«пор.» и т.п. (список усечённых — в `analysis/translations.py`).
